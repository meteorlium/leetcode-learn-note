# LLM模型量化

## 核心要点
量化的三重作用机制：
1. **显存压缩** - 主要目的，4:1压缩比使大模型能在消费级GPU运行
2. **Memory IO加速** - 减少75%数据传输，间接提速
3. **计算加速** - 需要硬件原生支持（如H100/A100的Tensor Core）

## 基本概念

### 显存占用对比
```python
# 70B模型显存需求
FP16: 70B × 2 bytes = 140GB    # 需要8张A100
W4A16: 70B × 0.5 bytes ≈ 35GB  # 1张A100即可
```

### 为什么LLM是Memory-bound
```python
# 生成阶段特点
计算量 = 2 × batch_size × seq_len × hidden_dim × vocab_size
内存访问量 = 模型参数量 × sizeof(dtype)

# batch_size和seq_len通常较小 → 计算密度低 → memory-bound
```

## 硬件支持差异

| 硬件类型 | INT4支持 | 加速效果 | 使用场景 |
|---------|---------|---------|---------|
| H100/A100 | Tensor Core原生支持 | 理论4x，实际2-3x | 生产环境 |
| RTX4090 | 部分支持，软件模拟 | 主要IO加速 | 开发测试 |
| 老旧GPU | 纯软件模拟 | 仅IO优化 | 资源受限场景 |

## 不同推理阶段的瓶颈

```python
# Prefill阶段：并行处理输入tokens
# - 计算密度高，可能compute-bound
# - 量化对计算加速更明显

# Generation阶段：逐个生成token  
# - 计算密度低，memory-bound占主导
# - 量化主要减少IO时间
```

## 面试标准答题框架

### 1. 核心目的（必答）
- 显存压缩：4:1压缩比，降低硬件门槛
- 成本优化：从数据中心级GPU到消费级GPU

### 2. 性能机制（技术深度）
- Memory IO减少75% → 间接加速
- 硬件INT4支持 → 直接计算加速
- KV Cache优化 → 支持更长上下文

### 3. Trade-off分析（加分项）
```
收益：显存↓75%, IO速度↑4x, 成本↓
代价：精度下降, 校准复杂度, 推理kernel复杂
```

### 4. 实际应用考虑
```python
def choose_quantization_strategy(gpu_memory: int, model_size: int, precision_req: str) -> str:
    if gpu_memory < model_size:
        return "必须量化" 
    elif precision_req == "critical":
        return "W8A16或FP16"
    else:
        return "W4A16平衡性价比"
```

## 常见面试延伸问题

1. **AWQ vs GPTQ vs PTQ的区别？**
   - AWQ：激活感知，保护重要权重通道
   - GPTQ：分组量化，逐层优化
   - PTQ：训练后量化，最简单但精度损失大

2. **量化如何与其他优化技术结合？**
   - Flash Attention：计算优化
   - PagedAttention：内存管理优化  
   - Speculative Decoding：推测执行加速
